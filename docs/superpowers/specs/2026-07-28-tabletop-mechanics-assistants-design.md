# 面杀机制辅助完善设计

## 目标

以移动版身份局现行技能为准，为实体面杀难以直接表达、或容易遗忘状态的技能补充手机辅助。辅助只解决线上机制，不代替实体牌堆、判定、摸牌和普通“选择一项”。

## 模块

### 0. 将面体力台

- 武将详情的将面旁直接记录当前体力、体力上限与护甲。
- “受到伤害”先扣等量护甲，超出的部分再扣体力，并保留伤害事件提示。
- “失去体力”无视护甲直接扣体力；“回复体力”不超过上限。
- 体力上限与护甲分别增减，护甲遵循移动版当前至多 5 点的通用规则。
- 每名武将的本局状态独立保存在本机，并可恢复为印刷初始值。

### 1. 标记台

- 自动识别技能文本中的“标记”“蓄力点”“护甲”等可变数值。
- 默认提供“自己、二号位至八号位”座次，可改名。
- 每个座次可添加武将建议的标记，也可添加自定义标记。
- 支持加一、减一、直接删除；本局状态保存在本机。
- 同页展示涉及该机制的现行技能，避免计数与规则脱节。

### 2. 扶汉选将

- 仅从当前身份局数据中的蜀势力武将抽取，排除赵襄本人和不可面杀武将。
- 使用无偏随机抽出五名且不重复。
- 可点开查看候选武将体力与基础技能，再确认替换目标。
- 输入本局累计移除的“梅影”数与游戏人数，直接给出调整后的体力上限，并提示最低体力时回复。

### 3. 谋弈

- 覆盖现行四名谋弈武将：谋徐晃、谋马超、界张嶷、韩玄。
- 发动者先私密选择，进入完全遮挡的交接页；对方确认接手机后再选择。
- 双方选择不同则谋弈成功，显示发动者所选谋略及对应技能效果；相同则显示被识破、无事发生。
- 隐藏选择只保存在当前组件内存，揭晓或关闭后不把答案留在本地存储。

### 4. 转换技

- 自动覆盖技能文本标注“转换技”的武将。
- 每个转换技独立记录阳/阴，默认阳；点击“发动并转换”后切换。
- 同时展示当前侧技能文本。
- 司马孚“蹇襄”按每名角色分别记录上次选择，下一次自动禁用相同选项。

## 数据与范围

- 模块分配由纯函数扫描 `heroes.json` 的移动版现行技能文本生成，防止数据刷新后漏挂。
- 现有化身、整经、水转百戏、精械、命运签、结党模块保持不变。
- 标记识别采用保守规则：明确出现“标记”“蓄力点”“护甲”的技能，以及移动版规则中明确的特殊数值资源；不把普通武将牌上的实体牌自动当作数字标记。
- 所有新增状态按“模块 + 武将编号”隔离并可一键本局重置。

## 验证

- 单元测试覆盖模块识别、标记提取、扶汉候选过滤与无重复随机、谋弈成功判定、转换状态和司马孚逐目标交替。
- 将面体力台测试覆盖伤害先扣护甲、失去体力无视护甲、回复上限和护甲上限。
- 数据测试确保兀突骨、赵襄、四名谋弈武将、转换技武将挂载正确。
- 完整构建、渲染测试和移动端界面检查通过后再部署。
